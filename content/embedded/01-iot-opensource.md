# 1. 사물인터넷과 오픈소스

## 사물인터넷 (IoT, Internet of Things)

> "모든 것들의 인터넷" — 작은 센서, 조명, 콘센트, 가전제품, 스마트기기, 자동차 등 **모든 기기가 인터넷에 연결**되어 유기적으로 통신하는 것

- **시작**: 스마트폰(아이폰) → 스마트패드/TV → 웨어러블(글래스, 워치)
- **4차 산업혁명의 핵심 기술**로 부상

### IoT 발전을 이끈 3요소

| 요소 | 내용 | 예시 |
|---|---|---|
| 저전력 기술 | 적은 전력으로 통신 | BLE, 6LoWPAN, MQTT |
| 오픈소스 | 소프트웨어 | 리눅스 |
| 오픈소스 하드웨어 | 하드웨어 | 아두이노, 라즈베리파이 |
| 오픈소스 컨텐츠 | 지식/콘텐츠 | 위키피디아, TED, YouTube |

## GNU 프로젝트와 자유소프트웨어

- **1983년 9월, 리처드 스톨만**이 시작
- **GNU = "GNU's Not Unix"** — 상용 OS인 유닉스 대신 자유롭게 쓸 수 있는 OS(**Hurd**)를 만들려던 프로젝트
- **1985년** 스톨만이 **GNU 선언문** 발표 + **자유소프트웨어재단(FSF)** 설립
- Hurd 개발이 지연되어 → 결국 **Linux**를 커널로 사용
- GNU 프로젝트가 개발한 소프트웨어: **gcc, gdb, GNOME**

**자유소프트웨어(free software)**
: 자유롭게 소스코드를 **사용 · 복사 · 수정 · 배포**할 수 있는 소프트웨어

---

## 자유소프트웨어 vs 프리웨어 vs 오픈소스

{: .시험 }
> `free`가 '공짜'인지 '자유'인지 혼동 → 1998년 2월 3일, 넷스케이프 브라우저 소스 공개 논의 회의에서 **'오픈소스'라는 용어**가 만들어짐

| 구분 | 무료 여부 | 소스코드 공개 |
|---|---|---|
| 프리웨어(freeware) | 무료 | **공개 안 함** |
| 자유소프트웨어 | 유료 또는 무료 | **공개해야 함** |
| 오픈소스 소프트웨어 | 유료 또는 무료 | **공개해야 함** |

### 자유소프트웨어 vs 오픈소스 (관점 차이)

| | 자유소프트웨어 | 오픈소스 소프트웨어 |
|---|---|---|
| 성격 | **사회적 운동** 측면 | **개발 방법론** 측면 |
| 주장 | "공유할 수 없는 독점 소프트웨어는 잘못됐다. 소스코드를 공개해서 모두 자유롭게 쓰자" | "당신의 코드를 다른 사용자가 변경하게 하면 그들이 버그를 고칠 것이다. 서로 에러를 고쳐 완성도를 높이자" |

- **오픈소스가 더 포괄적인 개념** (자유소프트웨어 ⊂ 오픈소스)
- 소프트웨어뿐 아니라 **하드웨어(설계도 공개), 글꼴 같은 데이터**에도 적용 가능

## 오픈소스 라이선스

{: .시험 }
> **"소스코드를 공개해야 하는가?"** 가 핵심 구분 기준. GPL만 공개 의무가 있고 나머지는 없다고 외우면 됨.

| 라이선스 | 소스 공개 의무 | 특징 |
|---|---|---|
| **GNU GPL** | **공개 필수** | 가장 많은 오픈소스가 채택. 소스를 수정하거나 새 코드를 병합하면 공개해야 함 |
| **GNU LGPL** | **불필요**(링크 시) | GPL의 공개 부담을 줄임. **라이브러리에 링크만 하는 경우** 공개 불필요 |
| **BSD** | 불필요 | GPL/LGPL보다 제한이 적어 허용 범위가 넓음 |
| **Apache** | 불필요 | 아파치 소프트웨어 재단이 자체 제작 |
| **MIT** | 불필요 | MIT가 소속 소프트웨어공학도를 돕기 위해 개발 |

### copyleft

- FSF가 자유소프트웨어를 위해 만든 것이 **GPL**
- **copyleft** = 저작권을 기반으로 자유롭게 공유한다는 GNU의 철학
- GPL 소프트웨어(Linux, gcc, gdb, GNOME)는 **배포 시 소스코드를 반드시 공개**

### 리눅스 배포판이 많은 이유

소스코드가 공개되므로 **재빌드해서 또 다른 리눅스를 배포**할 수 있기 때문.

- Debian → 재빌드 → **Ubuntu** (더 빠른 버전 업데이트 + 사용자 편의성 개선)
- RHEL(상용) → 재빌드 → **CentOS** (무료로 사용 가능)

## Linux

| 연도 | 사건 |
|---|---|
| 1991 | 핀란드의 **리누즈 토발즈**가 공개 |
| 1994 | 안정적인 **커널 1.0** 발표 |
| 1996 | **커널 2.0** 발표 |
| 1990년대 | IBM, Compaq, Oracle이 공식 지원 → **서버 시장**에서 두각 |
| 2000년대 | **임베디드** 분야 진출 |
| 2005년 이후 | 스마트 디바이스 OS로 사용 (안드로이드, 리모, 모블린, 마에모, 미고, 타이젠, WebOS) |

- 대형 기종용 **Unix를 개인용 컴퓨터에서 동작하도록 변형**한 것
- 초창기에는 **앤드루 타넨바움**이 교육용으로 만든 **미닉스(MINIX)** 유닉스 커널을 기반으로 제작
- 라이선스는 **GNU GPL**
- 현재 삼성전자, LG전자, 구글의 **스마트TV OS**로도 사용 중

### 대표 오픈소스

| 구분 | 예시 |
|---|---|
| 오픈소스 소프트웨어 | **Apache**(웹서버 점유율 60~70%), Linux 배포판(Debian/Ubuntu/RHEL/CentOS), GNOME·KDE, 안드로이드, 타이젠, 이클립스(IBM) |
| 오픈소스 하드웨어 | 비글보드, **아두이노**, **라즈베리파이**, 구글 코랄, 엔비디아 젯슨 |

## 오픈소스 하드웨어가 등장한 이유

초기 임베디드 교육의 문제점 3가지:

1. **값비싼** 임베디드 보드 → 진입 어려움
2. 저항·콘덴서·PCB 설계·납땜 등 **전자공학 전문지식** 요구
3. 하드웨어에서 프로그램을 구동하기 위한 **방대한 소프트웨어 지식** 요구

→ 비전공자뿐 아니라 **소프트웨어 전공자에게도 진입 장벽**으로 작용

→ 해결: 저렴하고 전문지식 없이도 접근 가능한 **오픈소스 하드웨어** 등장

## 아두이노 vs 라즈베리파이

{: .시험 }
> 두 보드의 **포지션 차이**(마이크로컨트롤러 vs 싱글보드 컴퓨터)를 묻기 좋음

| | 아두이노 (Arduino) | 라즈베리파이 (Raspberry Pi) |
|---|---|---|
| 출시 | **2005년**, 이탈리아 **마시모 반지** | **2012년 1월 29일**, 영국 **라즈베리파이 재단** |
| 목적 | 디자이너와 IT의 **융합인재 교육** | **기초 컴퓨터과학 교육** |
| 분류 | **저사양 마이크로컨트롤러 보드** | **싱글보드 컴퓨터(SBC)** |
| CPU | 8비트 AVR CPU (Atmel AVR) | ARM 기반 싱글/쿼드코어 + GPU + DSP |
| 메모리 | 매우 작음 | 대용량 (최대 8GB) |
| OS | 없음 | 있음 (Raspberry Pi OS 등) |
| 개발환경 | **스케치(sketch)** — C/C++ 몰라도 접근 가능 | 리눅스 + Python 등 |
| 전원 | 건전지 등 저전력 배터리로 구동 가능 | 어댑터 필요 |
| 가격 | UNO 기준 20달러 내외 | 재단이 비영리라 저렴 |

**라즈베리파이 추가 특징**

- 미국 **Broadcom**사의 **SoC(System on Chip)** 사용
- **OpenGL 지원 GPU** 탑재
- USB, GPIO, Ethernet, 무선랜, 블루투스, 사운드 출력, HDMI 등 지원
- 키보드·마우스·모니터를 연결하면 **소형 PC로 사용 가능**
- **모델 B = 유선랜(Ethernet) 포트 있음 / 모델 A = 없음**
