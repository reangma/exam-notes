2. 자연어 임베딩 (Word Embedding)#

이 장의 한 줄 요약#

컴퓨터는 숫자만 안다 → 그래서 단어를 숫자 목록(벡터)으로 바꿔야 한다 → 어떻게 바꾸는 게 좋은가?

이 장은 "단어를 숫자로 바꾸는 방법"이 어떻게 발전했는지의 이야기입니다.

ASCII 코드         → 그냥 번호표. 의미 없음 (실패)
One-hot encoding   → 단어마다 자리 하나. 너무 크고 의미 없음
TF-IDF             → 중요도 점수를 줌. 그래도 크고 문맥을 모름
Dense (밀집 표현)  → 짧고, 의미가 담긴 숫자. 비슷한 단어는 비슷한 숫자 ✅

참고

벡터, 코사인 유사도, log, 희소 행렬이라는 말이 나옵니다. 모르면 0장을 먼저 보세요. 아주 짧게: 벡터 = 숫자 목록, 희소 = 대부분이 0, log = 큰 숫자를 작게 눌러주는 도구

1. 기계가 자연어를 처리하는 방법#

자연어(natural language) = 사람이 쓰는 말 (한국어, 영어 등). 프로그래밍 언어의 반대말입니다.

기계는 왜 말을 못 알아듣나?#

컴퓨터에게 "사과" 라는 글자는 그냥 모양일 뿐입니다. 먹는 사과인지, 미안하다는 사과인지 전혀 모릅니다. 컴퓨터가 계산할 수 있는 건 숫자뿐이므로 → 기계가 이해할 수 있는 언어(숫자)로 바꾸어야 합니다.

처리 순서#

Tokenization  →  Vocabulary  →  Word
(글 자르기)       (단어 사전 만들기)  (단어 하나를 어떻게 표현할까?)
단계 쉬운 뜻 예시
Tokenization 문장을 작은 조각(토큰)으로 자르기 "나는 학생이다" → ["나는", "학생", "이다"]
Vocabulary 나온 조각들을 모아 단어 사전 만들기 {나는, 학생, 이다, 사과, …}
Word 사전 속 단어 하나를 숫자로 어떻게 표현할까? "학생" → ???

가장 어려운 단계는 마지막#

"단어 하나를 어떻게 표현할까" = "단어의 의미를 어떻게 정의할까" 의 문제이고, 슬라이드는 이렇게 말합니다.

  • 가장 기초적이지만 가장 어려운 문제
  • 단어는 겉으로 보이는 형태와 달리 여러 가지 뜻을 내포 → 그 뜻에 따라 문장의 내용과 의미가 바뀔 수 있음
  • 언어는 효율성을 극대화하는 방향으로 발달(진화) 해 왔음
  • 효율성을 높이는 과정에서 정보량이 낮은 정보들이 생략됨

참고

"효율성 때문에 정보가 생략된다"는 게 무슨 말? 친구에게 "밥 먹었어?"라고 하지 "너는 오늘 점심시간에 식사를 하였는가?"라고 하지 않죠. 사람은 뻔한 건 빼고 짧게 말합니다. 듣는 사람이 알아서 채워 들으니까요. 그런데 컴퓨터는 그 빠진 부분을 채울 능력이 없습니다. 그래서 어렵습니다.

2. 단어의 유사성과 모호성#

언어의 효율성은 단어에도 나타납니다. 한 단어에 여러 뜻을 몰아넣는 방식으로요.

표제어 (Lemma)
겉으로 보이는 단어의 형태(글자). 사전에서 찾을 때 쓰는 대표 단어. 이 하나의 형태 안에 여러 의미가 들어 있음

예시 — "배"#

같은 글자 "배" 의미
배 ① 사람이나 동물의 몸에서 위장, 창자, 콩팥 따위의 내장이 들어 있는 곳
배 ② 배나무의 열매
배 ③ (물 위의 탈것) …

글자는 하나인데 뜻이 여러 개 → 이걸 중의성(모호성) 문제라고 하며, 자연어처리에서 매우 중요한 문제입니다.

              ┌─ 의미 1
   단어 1 ────┼─ 의미 2         ← 단어 1, 2가 같은 형태를 공유하지만
              └─ 의미 3            서로 다른 뜻을 가질 수 있음
   단어 2 ────┬─ 의미 4
              └─ 의미 5

왜 어려운가 (슬라이드 3가지)#

  1. 상황에 따라 다른 의미로 쓰일 수 있음 → 사람도 이해하기 어려움 - "배가 아프다" (몸) / "배가 맛있다" (과일) / "배가 떠난다" (탈것)
  2. 주변 정보가 부족하면 의미적 모호성이 증가 - 그냥 "배" 한 글자만 주면 아무도 모름
  3. 내가 가진 과거 기억이나 사전 지식 때문에 주변 정보를 다르게 해석 - 어부는 "배"를 들으면 탈것을, 과일가게 사장님은 과일을 먼저 떠올림

시험 포인트

예상 문제: "자연어처리에서 단어 표현이 어려운 이유를 쓰시오"

모범 답안: 하나의 표제어(형태) 안에 여러 의미가 공존하는 중의성 때문이다. 같은 단어도 상황에 따라 다른 의미로 쓰이며, 주변 정보(문맥)가 부족하면 모호성이 커지고, 사람마다 가진 사전 지식에 따라 해석이 달라질 수 있다.

3. 단어의 표현 — 단순한 방법은 실패한다#

가장 단순한 방법: 번호표 붙이기 (ASCII code 등)#

ASCII 코드 = 컴퓨터가 글자를 저장하는 번호표입니다. 예: A = 65, B = 66.

이렇게 각 글자/단어에 번호를 붙이면 컴퓨터가 저장은 할 수 있지만…

  • "이 단어가 무엇인지" 알려주는 것 외에 아무 정보가 없음
  • 단어의 의미에 대한 정보 X
  • → 컴퓨터가 단어의 표상(겉모습)에만 집중하게 됨 → 의미의 모호성을 포착할 만큼 충분한 정보를 줄 수 없음

참고

학생에게 학번을 붙이는 것과 같습니다. 학번 2023001과 2023002는 숫자가 가깝지만, 두 학생이 비슷한 사람이라는 뜻은 전혀 아니죠. 번호는 "누구인지 구별"만 해줄 뿐, "어떤 사람인지"는 알려주지 않습니다. 단어도 마찬가지입니다.

그래서 생기는 3가지 요구사항#

자연어를 숫자로 바꾸는 건 결국 정보를 압축하는 일입니다. 그래서 고민할 것:

  1. 자연어를 변환할 때 어떤 정보를 압축시킬 것인가?
  2. 정보 압축 과정에서 어떤 손실이 발생할 수 있는가?
  3. 발생하는 손실은 어떻게 줄일 수 있는가?

4. Embedding (임베딩) ★#

특징 추출 (Feature extraction)
데이터마다 어떤 특징을 가지고 있는지 찾아내고, 그것을 벡터(숫자 목록)로 변환하는 작업
임베딩 (Embedding)
자연어 처리에서 특징 추출을 통해 자연어를 수치화하는 과정 (자연어 → 벡터)
  • (예시) 학생 → [0, 1, 0, 1, 0, 0, …, 0, 1]
  • 2003년 "A Neural Probabilistic Language Model" 논문에서 처음 소개
  • 이름의 뜻: 단어나 문장을 벡터로 바꿔서 벡터 공간에 "끼워 넣는다(embed)"

참고

"벡터 공간에 끼워 넣는다"를 그림으로 상상하기

커다란 지도가 있다고 생각하세요. 단어 하나하나를 지도 위의 한 점에 찍습니다. - "강아지", "고양이", "햄스터"는 서로 가까운 곳에 (동물 동네) - "사과", "바나나", "포도"는 또 다른 동네에 (과일 동네)

이렇게 의미가 비슷하면 가까이, 다르면 멀리 배치하는 것이 좋은 임베딩입니다. 실제로는 2차원 지도가 아니라 수백 차원 공간이지만 원리는 같습니다.

Embedding의 두 가지 역할 ★#

시험 포인트

임베딩의 역할 2가지는 단답 단골입니다. ① 자연어의 의미적인 정보 함축 ② 자연어 간 유사도 계산

역할 ① 자연어의 의미적인 정보 함축#

함축 = 짧은 것 안에 많은 뜻을 담는 것.

  • 자연어의 중요한 특징을 추출 → 벡터로 압축
  • 임베딩으로 표현된 문장은 실제 자연어의 주요 정보를 포함
  • 주요 정보: 의미적, 문법적, 구조적, …
  • 다양한 특징을 표현 → 언어의 복잡성과 모호성까지 설명할 수 있음
  • 사칙연산 가능 → 단어들 사이의 의미적, 문법적 관계 도출 가능

"단어로 사칙연산을 한다"? — 이게 임베딩의 신기한 점입니다.

성능 평가: 단어 유추 평가 (Word analogy test)#
(첫 번째 단어 벡터) − (두 번째 단어 벡터) + (세 번째 단어 벡터) = ?

    아들   −   딸    +   소년   =   ?   →  소녀

이 테스트가 확인하려는 것

"아들 : 딸 = 소년 : 소녀" 라는 관계가 벡터 안에 들어 있는지입니다.

  1. 두 단어를 빼면 → 공통점은 지워지고 차이점만 남습니다. - 아들과 딸의 공통점: 자식 / 차이점: 성별 - 그래서 아들 − 딸 = "성별 차이"를 나타내는 화살표
  2. 소년과 소녀의 차이도 똑같이 성별이죠.
  3. 좋은 임베딩이라면 두 "성별 화살표"가 같은 방향·같은 길이로 만들어져 있습니다.
  4. 그러면 벡터 덧셈·뺄셈으로 짝이 되는 단어(소녀)를 찾아낼 수 있습니다.

주의

수학적으로 정확히 쓰면 딸 − 아들 + 소년 = 소녀 가 맞는 방향입니다(아들→딸로 가는 화살표를 소년에 더하면 소녀). 슬라이드는 아들 − 딸 + 소년 = 소녀 로 적혀 있는데, 핵심은 "두 쌍의 관계가 벡터에 똑같이 담겨 있는가" 이므로 시험에서는 슬라이드 식 그대로 쓰고, 의미(관계가 보존된다)를 설명하면 됩니다.

참고

더 유명한 예시로 이해하면 쉽습니다. 왕 − 남자 + 여자 = 여왕 - 왕에서 "남자다움"을 빼고 "여자다움"을 더하면 → 여왕

이게 된다는 건 "성별"이라는 개념이 벡터 안에 하나의 방향으로 들어 있다는 뜻입니다. 컴퓨터가 단어의 의미 관계를 숫자로 이해하고 있는 거죠.

슬라이드 결론: "아들-딸의 관계와 소년-소녀 간 의미 차이가 임베딩에 함축되어 있으면, 성능 좋은 임베딩임을 간접적으로 확인할 수 있음" (실습: word2vec.kr/search/)

역할 ② 자연어 간 유사도 계산#

  • 컴퓨터는 여러 개의 특징 차원으로 구성된 공간 위에서 사람처럼 벡터의 의미 해석 가능
  • 유사도 계산 방법을 활용하여 두 벡터(두 단어) 간 얼마나 비슷한지 계산 가능
코사인 유사도 (Cosine similarity)
두 벡터 간의 코사인 각도를 이용하여 두 벡터의 유사도를 계산. −1 ~ 1 사이의 값으로 표현, 1에 가까울수록 유사도 높음

쉽게: 두 단어를 각각 화살표라고 생각하고, 두 화살표가 얼마나 같은 방향을 보는지 재는 것입니다.

두 화살표 각도 값 예
거의 같은 방향 0도 1에 가까움 "강아지" vs "멍멍이"
직각 90도 0 "강아지" vs "민주주의"
정반대 180도 −1 (반대 의미)
벡터 공간 시각화
단어 벡터는 수백 차원이라 눈으로 볼 수 없음 → 차원 축소 기법으로 저차원(2~3차원)으로 줄여서 그림으로 그림. 대표 기법: t-SNE, PCA

참고

차원 축소 = 입체 물체에 빛을 비춰 벽에 그림자를 만드는 것과 같습니다. 정보는 조금 잃지만 대략적인 모양은 볼 수 있습니다. t-SNE, PCA는 그 "그림자 만드는 방법"의 이름입니다.

중요

숫자로 외울 것: 코사인 유사도 범위 = −1 ~ 1, 1에 가까울수록 유사

Embedding 기법의 발전 3단계#

통계 기반의 자연어처리  →  딥러닝 기반의 자연어처리  →  전이학습 기반의 자연어처리
 (One-hot, TF-IDF)          (Word2Vec, RNN 등)         (BERT, GPT 등)
   ↓ 이 장 5~7절              ↓ 이 장 8~9절               ↓ 3~4장

5. 출현 빈도 기반 임베딩 ① — One-hot encoding ★#

"단어가 몇 번 나왔나(출현 빈도)"를 기반으로 하는 가장 기초적인 방법 두 가지가 One-hot과 TF-IDF입니다.

개념#

말 그대로 딱 한 자리만 뜨겁게(hot = 1), 나머지는 전부 0으로 표현합니다.

  • 자연어 코퍼스(전체 글 모음) 안의 전체 단어 개수 = 벡터의 길이(차원)
  • 표현하고 싶은 단어의 자리(인덱스)만 1, 나머지는 0

예시 — 단어가 4개면 벡터 길이도 4#

단어 사전: 초등학생, 중학생, 고등학생, 대학생 → 벡터의 차원 = 4

단어 1번 자리 2번 자리 3번 자리 4번 자리 벡터
초등학생 1 0 0 0 [1, 0, 0, 0]
중학생 0 1 0 0 [0, 1, 0, 0]
고등학생 0 0 1 0 [0, 0, 1, 0]
대학생 0 0 0 1 [0, 0, 0, 1]

참고

출석부를 생각하세요. 반 학생이 4명이면 칸이 4개고, "초등학생"을 부르면 그 칸에만 체크(1) 합니다.

One-hot encoding의 한계 2가지 ★★#

시험 포인트

거의 확정 출제 포인트. ① 희소 문제(Sparsity problem) ② 단어의 유사도를 표현할 수 없음

한계 ① 희소 문제 (Sparsity problem)#

희소(sparse) = 드문드문하다, 대부분 비어 있다.

  • 실제 글 모음(코퍼스)에는 최소 몇 만 개의 단어가 있음
  • (예시) 단어 사전 크기가 20,000개라면:
  • 벡터 길이도 20,000
  • 그중 1개 자리만 1
  • 나머지 19,999개는 0
  • → 대부분의 값이 0인 희소 행렬(Sparse matrix) 이 됨
  • → 단어가 늘어날수록 표현의 효율성 저하 (쓸모없는 0이 점점 많아짐)
  • → 단어 사전이 커질수록 공간 복잡도 증가 (저장 공간이 계속 커짐)

참고

공간 복잡도 = "얼마나 많은 저장 공간이 필요한가". 커질수록 메모리를 많이 잡아먹습니다.

비유: 단어 하나를 저장하려고 2만 칸짜리 서류를 쓰는데, 거기 적힌 건 체크 표시 하나뿐. 나머지 19,999칸은 백지. 엄청난 종이 낭비죠.

한계 ② 단어의 유사도를 표현할 수 없음#

  • 모든 단어들 간의 거리가 동일 → 유사도 판단 불가
  • (예시) 중학교 [1,0,0], 고등학교 [0,1,0], 대학교 [0,0,1]
       z (대학교)
       │
       │
       └──────── y (고등학교)
      /
     x (중학교)

  세 단어가 서로 직각(90도)으로 떨어져 있음
  → 어느 둘을 골라도 거리가 똑같음

문제: 사람이 보기엔 "중학교-고등학교"가 "중학교-대학교"보다 더 비슷한데, One-hot에서는 셋 다 똑같이 남남입니다. 코사인 유사도를 재도 전부 0(직각)이 나옵니다.

6. 출현 빈도 기반 임베딩 ② — TF-IDF ★★#

개념#

TF-IDF (Term Frequency – Inverse Document Frequency)

이름이 길지만 뜻은 간단합니다. 단어에 "중요도 점수"를 매기는 방법입니다.

부분 풀네임 쉬운 뜻 묻는 질문
TF Term Frequency (단어 빈도) 이 문서에 이 단어가 얼마나 자주 나오나 "이 글에서 많이 나와?"
IDF Inverse Document Frequency (역 문서 빈도) 전체 문서 중에 이 단어가 얼마나 희귀한가 "다른 글에도 다 나와? 아니면 이 글에만 나와?"
  • 문서-단어 행렬 안의 각 단어에 중요한 정도만큼 가중치(점수) 를 주는 방법
  • 활용: 문서의 유사도 계산, 검색 시스템에서 검색 결과의 중요도 결정, 문서 내 특정 단어의 중요도 계산 등에 효율적

직관 — 왜 두 개를 곱하나?#

참고

"자기소개서에서 그 사람을 대표하는 단어"를 찾는다고 해 봅시다.

  • "저는", "그리고", "했습니다" → 모든 자소서에 다 나옴 → 이 사람만의 특징이 아님 ❌
  • "드론 대회 우승" → 이 사람 자소서에만 여러 번 나옴 → 이 사람을 대표함 ✅

즉 좋은 키워드는: 1. 이 문서에 자주 나오고 (TF가 높고) 2. 다른 문서엔 잘 안 나와야 합니다 (IDF가 높고)

그래서 TF × IDF 입니다. 둘 다 높아야 점수가 높아집니다.

공식 (슬라이드 그대로)#

기호부터 정리합니다.

기호 뜻
d 문서 (document) 하나
t 단어 (term) 하나
n (또는 N) 전체 문서의 개수
f(t,d) 문서 d 안에서 단어 t가 나온 횟수
Σₖ f(k,d) 문서 d에 나온 모든 단어 횟수의 합 = 그 문서의 총 단어 수 (Σ = 전부 더하기)
df(t) 단어 t가 등장한 문서의 수 (document frequency) 
         문서 d 안에서 단어 t가 나온 횟수
tf(d,t) = ─────────────────────────────────
         문서 d의 전체 단어 수

                  n (전체 문서 수)
idf(d,t) = log( ──────────────────── )
                 1 + df(t) (단어가 나온 문서 수)

TF-IDF = tf × idf

공식을 말로 풀면#

TF 부분 - "이 문서 전체 단어 중에서, 이 단어가 차지하는 비율" - 예: 단어 100개짜리 글에 "AI"가 5번 → TF = 5/100 = 0.05

IDF 부분 - df(t) 가 크다 (여러 문서에 나온다) → 분모가 커짐 → 분수가 작아짐 → IDF 작음 → 흔한 단어라 덜 중요 - df(t) 가 작다 (몇 문서에만 나온다) → 분모가 작아짐 → 분수가 커짐 → IDF 큼 → 희귀한 단어라 중요 - 슬라이드 표현: "idf는 df(t)에 반비례 → 여러 문서에 공통적으로 많이 나오는 단어는 중요도가 낮음을 의미"

참고

반비례 = 하나가 커지면 다른 하나는 작아지는 관계. 시소처럼요.

Why log? — log를 왜 쓰나 ★★#

시험 포인트

아주 전형적인 질문입니다. 답은 2가지: ① 가중치를 적절히 조절하기 위해서 ② 분모가 0이 되는 경우(특정 단어가 문서 전체에서 등장하지 않는 경우) 방지

① 가중치를 적절히 조절 — log의 역할

log는 큰 숫자를 작게 눌러주는 도구입니다 (0장 3절).

문서가 100만 개이고 어떤 단어가 딱 1개 문서에만 나왔다고 하면:

log 없이 :  1,000,000 ÷ 1      = 1,000,000   ← 점수가 폭발!
log 쓰면 :  log(1,000,000)     = 6           ← 적당한 점수

log가 없으면 희귀 단어 하나가 점수 백만 점을 받아서 다른 모든 단어를 압도해 버립니다. log로 눌러서 점수 차이를 적당하게 만드는 것입니다.

② 분모가 0이 되는 것 방지 — 1 + 의 역할

  • 어떤 단어가 어느 문서에도 안 나왔다면 df(t) = 0
  • 그러면 n ÷ 0 → 0으로 나누기는 계산 불가 (수학에서 금지)
  • 그래서 분모에 1을 더해서 1 + df(t) 로 만듦 → 최소 1이 되므로 안전

중요

엄밀히 말하면 ②는 log가 아니라 분모의 1 + 가 해주는 일입니다. 슬라이드가 "Why log?" 아래에 둘 다 묶어 놓았으므로 시험에서는 2가지를 같이 쓰면 됩니다.

TF-IDF 계산 예시 (슬라이드) — 한 단계씩 ★#

상황

  • 전체 문서 수 N = 3
  • 계산할 단어: "AI"
문서 내용 단어 수
d1 "AI is the future" 4개 (AI, is, the, future)
d2 "AI and data science" 4개 (AI, and, data, science)
d3 "Data is important" 3개

1단계 — TF 구하기 ("각 문서 안에서 AI가 차지하는 비율")

문서 AI 등장 횟수 전체 단어 수 TF
d1 1번 4개 1 ÷ 4 = 0.25
d2 1번 4개 1 ÷ 4 = 0.25
d3 0번 – 0

2단계 — IDF 구하기 ("AI가 얼마나 희귀한가")

  • AI가 등장한 문서 수 = d1, d2 → 2개
  • IDF("AI") = log(N ÷ df) = log(3 ÷ 2) = log(1.5) ≈ 0.176

3단계 — TF × IDF

문서 TF × IDF = TF-IDF
d1 0.25 × 0.176 ≈ 0.044
d2 0.25 × 0.176 ≈ 0.044
d3 0 × 0.176 = 0

4단계 — "만약 future 또는 science 단어라면?" (슬라이드 질문)

  • "future"는 d1에만, "science"는 d2에만 나옵니다 → df = 1 → 더 희귀함 → IDF가 더 큼
단어 문서 d1 문서 d2 문서 d3 IDF
AI TF = 1/4 = 0.25 → 0.044 TF = 1/4 = 0.25 → 0.044 TF = 0 → 0 log(3/2) ≈ 0.176
future TF = 1/4 = 0.25 → 0.275 TF = 0 → 0 TF = 0 → 0 log(3/1) ≈ 1.099
science TF = 0 → 0 TF = 1/4 = 0.25 → 0.275 TF = 0 → 0 log(3/1) ≈ 1.099

중요

결론 (계산 문제가 나오면 반드시 같이 쓰기) 한 문서에만 나오는 단어(future, science: 0.275)가 여러 문서에 나오는 단어(AI: 0.044)보다 TF-IDF 점수가 훨씬 높다. → TF-IDF는 그 문서를 특징짓는 단어에 높은 점수를 준다.

주의

슬라이드 숫자의 함정 (알고만 있으세요) - 공식에는 분모가 1 + df(t) 인데, 예시 계산은 +1 없이 log(N/df) 로 했습니다. - 또 0.176은 밑이 10인 log(log₁₀ 1.5), 1.099는 밑이 e인 자연로그(ln 3) 값이라 두 줄의 log 종류가 다릅니다. - 시험에서 계산을 시키면 문제에 주어진 공식·조건을 따르면 되고, 이 표가 그대로 나오면 슬라이드 숫자를 그대로 쓰는 게 안전합니다. 결론(희귀 단어일수록 점수가 높다)은 어느 쪽이든 같습니다.

7. Sparse representation (희소 표현)#

One-hot과 TF-IDF의 공통된 한계입니다.

  • 표현하고 싶은 단어 자리만 1(또는 점수), 나머지는 0으로 채우는 방식
  • → 벡터 또는 행렬의 대부분이 0으로 저장 → 이걸 Sparse representation (희소 표현) 이라고 부름
  • One-hot encoding으로 만든 벡터 = sparse vector (희소 벡터)

참고

TF-IDF도 희소한가요? 네. TF-IDF 벡터도 길이가 단어 사전 크기이고, 그 문서에 안 나온 단어 자리는 전부 0입니다. 한 문서에 나오는 단어는 사전 전체에 비하면 극히 일부니까 대부분이 0이죠. 0 대신 점수(실수) 가 들어간다는 것만 다릅니다.

One-hot vs TF-IDF 비교표 ★#

구분 원핫 인코딩 (One-hot) TF-IDF
표현 방식 단어 → 0과 1 벡터 구성 단어 → 중요도 가중치 벡터
벡터 차원 어휘 크기만큼 어휘 크기만큼
값 분포 0과 1 0과 가중치(실수)
장점 단순, 구현 쉬움 단어 중요도 반영, 검색/분류에 효과적
한계 의미 정보 없음, 차원 크다 문맥 무시, 희소성, 동의어/다의어 처리 불가

시험 포인트

표 채우기로 나오기 좋습니다. 특히: - 공통점: 둘 다 벡터 차원 = 어휘(단어 사전) 크기, 둘 다 희소 - TF-IDF의 한계 단어 3개: 문맥 무시 / 희소성 / 동의어·다의어 처리 불가

참고

용어 풀이 - 문맥 무시: "나는 배가 아프다"와 "배를 깎아 먹었다"의 "배"를 같은 단어로 취급함 (단어 횟수만 세니까) - 동의어: 뜻이 같은 다른 단어 (강아지 = 멍멍이). TF-IDF는 이 둘을 전혀 다른 단어로 봄 - 다의어: 한 단어에 뜻이 여럿 (배 = 몸/과일/탈것). TF-IDF는 이걸 구별 못 함

8. Dense representation (밀집 표현) ★★#

딥러닝 기반 모델에서 쓰는 방식이며, 희소 표현의 문제를 해결합니다.

밀집 표현 (Dense representation)
벡터의 차원이 조밀(dense)해졌다는 의미 - 더 이상 벡터의 차원을 단어 집합의 크기로 설정하지 않음 - → 사용자가 설정한 값으로 모든 단어 벡터의 차원을 맞춤 (예: 300) - 0과 1의 binary가 아닌 연속적인 실수값으로 인코딩됨

(예시) 강아지 → [0.12, 0.84, 0.11, 0.34, 0.45] (fixed size, dim = 5)

참고

비교해 보세요

One-hot  강아지 = [0, 0, 0, 1, 0, 0, …, 0]   ← 길이 20,000, 숫자 1개만 의미 있음
Dense    강아지 = [0.12, 0.84, 0.11, 0.34, 0.45]   ← 길이 5, 숫자 전부 의미 있음

Dense의 각 칸은 "동물스러움 0.84", "크기 0.11" 처럼 어떤 특징의 정도를 나타낸다고 상상하면 됩니다. (실제로는 사람이 이름 붙일 수 없는 특징들이지만, 원리는 이렇습니다)

참고

binary / 실수 / 연속적 - binary(이진): 0 아니면 1, 둘 중 하나 - 실수: 0.12, 0.84 처럼 소수점이 있는 숫자 - 연속적: 0과 1 사이 아무 값이나 될 수 있음

Dense representation의 특징 ★#

  1. 적은 차원으로 대상을 표현 가능 (2만 칸 → 300칸)
  2. 각각의 차원들이 모두 어느 정도의 정보를 포함 → 모델 학습이 수월함
  3. 단어 사전의 크기가 증가하더라도 차원의 크기는 일정 → 공간 복잡도 개선 - 단어가 2만 개든 10만 개든 벡터 길이는 300 그대로
  4. 더 큰 일반화 능력(generalization) 을 가짐
  5. 의미 이해 & 정보 검색 향상

특징 4 — 일반화 능력 (슬라이드 예시) ★#

시험 포인트

그대로 외우면 좋은 예시

'강아지'는 자주 출현하고, '멍멍이'는 적게 출현한다고 할 때: - 희소 표현 → '강아지'-'멍멍이' 간의 관계가 전혀 표현되지 않음 → '멍멍이'를 따로 학습해야 함 - 밀집 표현 → '강아지'와 '멍멍이'가 서로 비슷한 벡터로 표현됨 → 일반화 가능

쉽게 풀면: - 데이터에서 "강아지"는 1만 번 나오고 "멍멍이"는 10번만 나왔다고 합시다. - 희소 표현: 두 단어가 완전히 남남이라, "강아지"로 배운 지식이 "멍멍이"에게 전혀 전달 안 됨. 10번 나온 걸로 따로 배워야 해서 잘 모름. - 밀집 표현: 두 단어가 비슷한 위치에 있으니, "강아지"로 배운 지식이 "멍멍이"에도 자동으로 적용됨. 이게 일반화입니다.

참고

일반화(generalization) = 배운 걸 처음 보는 경우에도 적용하는 능력. "이 문제 풀어봤으니 비슷한 문제도 풀 수 있다"는 것.

특징 5 — 의미 이해 & 정보 검색 향상#

(1) 질문과 답을 같은 공간에 놓기

"What is the capital of France?"   →  [Question Encoder]  ┐
                                                          ├→ Dense embedding (같은 공간)
"Paris is the capital of France"   →  [Context Encoder]   ┘

두 인코더의 가중치는 "벡터 차이를 최소화하도록(minimize vector difference)" 함께 최적화됨
  • 인코더(encoder) = 글을 받아서 벡터로 바꿔주는 장치
  • 질문용 인코더와 문서용 인코더를 같이 훈련시켜서, 질문과 그 정답 문장이 가까운 벡터가 되게 만듦
  • 그 결과 의미가 비슷한 것끼리 공간에 모임 (예: monday, tuesday, wednesday, thursday, friday, saturday, sunday 가 한 동네에 뭉쳐 있음)

(2) 정보 검색 동작 예시 (임베딩된 단락 활용)

문서를 단락별로 미리 벡터로 바꿔 두고, 질문이 오면 가장 비슷한 단락을 고릅니다.

[미리 저장해 둔 단락 벡터]
1번 단락 (IDC 시장 성장률 이야기)       : [0.1, 0.5, 0.9, … , 0.1, 0.2]
2번 단락 (AI 애플리케이션 시장 이야기)  : [0.7, 0.1, 0.3, … , 0.5, 0.6]
3번 단락 (AI SIS·AD&D 이야기)           : [0.9, 0.4, 0.5, … , 0.4, 0.3]

[질문이 들어옴]
"시장조사기관 IDC가 예측한 AI 소프트웨어 시장의 연평균 성장률은 어떻게 되나요?"
  → 질문 벡터: [0.1, 0.5, 0.9, … , 0.2, 0.4]

[유사도 계산]
  1번: 80%  → 선택!   (질문 벡터와 모양이 거의 같음)
  2번: 30%
  3번: 25%

참고

질문 벡터 [0.1, 0.5, 0.9, …] 와 1번 단락 [0.1, 0.5, 0.9, …] 가 앞부분이 거의 같죠? 그래서 유사도가 높게 나옵니다. 이 원리가 8장의 RAG(검색해서 답하기) 의 핵심입니다.

Sparse vs Dense 최종 비교 ★#

중요

구분 Sparse (One-hot, TF-IDF) Dense (딥러닝 임베딩)

9. AutoEncoder (오토인코더) ★#

밀집 표현을 스스로 배우는 대표적인 구조입니다.

  • "Learning Internal Representation by Error Backpropagation" (1986) 논문에서 처음 소개
  • 일반적으로 3개의 계층(층) 으로 구성
  • Label(정답)이 없는 데이터로부터 낮은 차원의 특성 표현을 학습하는 비지도 학습
   입력 X          Latent vector Z        출력 X̃
 (원래 데이터)      (압축된 핵심)        (복원한 데이터)

  ●●●●●●●●   →      ●●●       →      ●●●●●●●●
  (넓음)          (좁음, 저차원)         (넓음)
        압축(encode)        복원(decode)
층 이름 역할
1층 입력 계층 X 원래 데이터
2층 Latent vector Z 입력 데이터의 정보를 압축하고 있는 벡터 (핵심만 남긴 것)
3층 출력 계층 X̃ (엑스 틸드) Z를 보고 원래 데이터를 복원한 것

어떻게 학습하나? — "요약했다가 다시 풀어쓰기"#

참고

비유: 책 한 권을 3줄 요약 → 그 3줄만 보고 다시 책을 써보기

  1. 긴 책(입력 X)을 3줄로 요약합니다 (Latent vector Z).
  2. 그 3줄만 보고 원래 책을 다시 써 봅니다 (출력 X̃).
  3. 다시 쓴 책이 원래 책과 비슷하면 → 요약을 잘한 것, 다르면 → 요약을 고쳐야 함.
  4. 이걸 반복하면 3줄 요약(Z) 안에 책의 핵심이 압축되어 들어가게 됩니다.

이때 정답지가 필요 없습니다. "원래 책" 자체가 정답이니까요. 그래서 비지도 학습입니다.

  • Latent(잠재) = 겉으로 드러나지 않고 숨어 있는. 데이터 속에 숨은 핵심 특징이라는 뜻
  • Backpropagation(역전파) = 틀린 정도를 거꾸로 전달하며 모델을 고치는 학습 방법 (0장 8절)

시험 포인트

AutoEncoder로 물어볼 것 3가지: ① 3계층 구조: 입력 X / Latent vector Z / 출력 X̃ ② Label 없는 데이터로 학습하는 비지도 학습 ③ 낮은 차원의 특성 표현(압축된 표현)을 학습 (+ 1986년 논문에서 처음 소개)
