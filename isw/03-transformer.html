3. Seq2Seq와 Transformer#

이 장의 한 줄 요약#

단어를 숫자로 바꿨으면(2장), 이제 "문장"을 처리할 모델이 필요하다. RNN(한 단어씩 읽기) → Seq2Seq(다 읽고 요약해서 번역) → Transformer(한꺼번에 읽고, 서로 참고하기)

각 단계가 앞 단계의 문제를 어떻게 고쳤는지만 따라가면 이 장은 끝납니다.

RNN         : 한 단어씩 순서대로 읽는다      → 문제: 입출력 길이가 고정됨
Seq2Seq     : 다 읽고 → 요약 → 번역한다      → 문제: 요약 1개에 다 넣느라 정보 손실, 느림
Transformer : 한꺼번에 읽고, 단어끼리 참고  → 해결! (지금 GPT, Claude의 뼈대)

1. 배경 — RNN 계열 모델과 그 한계#

시계열 데이터란?#

시계열(Time series) 데이터
순서가 중요한 데이터. 소리 데이터, 자연어 등의 언어 정보

참고

"나는 너를 좋아해" 와 "너는 나를 좋아해" 는 같은 단어인데 순서가 달라서 뜻이 다릅니다. 이렇게 순서가 의미를 결정하는 데이터를 시계열(순차) 데이터라고 합니다.

DNN(심층 신경망) 기반 모델이 이런 시계열 데이터 처리에서도 준수한 성과를 보였고, 대표 모델이 셋 있습니다.

모델 풀네임 쉬운 설명
RNN Recurrent Neural Network (순환 신경망) 한 단어씩 순서대로 읽으면서, 앞에서 읽은 내용을 메모장(hidden state) 에 적어 다음으로 넘기는 모델
LSTM Long-Short Term Memory RNN의 기억력 개선판. 중요한 건 오래 기억하고 필요 없는 건 잊는 장치(gate, 문) 를 달았음
GRU Gated Recurrent Unit LSTM을 더 단순하게 만든 버전

참고

RNN 작동 방식 비유: 책을 한 글자씩 읽으며 메모하기

"I"   를 읽음 → 메모: [I]
"am"  를 읽음 → 메모 갱신: [I am]
"a"   를 읽음 → 메모 갱신: [I am a]
"student" 읽음 → 메모 갱신: [I am a student]

이 메모장을 hidden state(은닉 상태) 라고 부릅니다. 앞 단어를 다 읽어야 다음 단어로 넘어갈 수 있습니다.

RNN의 한계 — 입력/출력 크기가 고정#

중요

모델의 입력/출력 크기가 고정된다는 명확한 한계가 존재 그런데 자연어, 소리 등은 가변적인 길이의 입출력을 가집니다.

예: 기계 번역기 (Machine Translator)

I am a student        (영어 4단어)
     ↓
je suis étudiant      (프랑스어 3단어)
  • 입력은 4단어인데 출력은 3단어 → 길이가 다릅니다
  • 한국어 → 영어 번역도 마찬가지: "너 지금 뭐해?" (3~4단어) ↔ "What are you doing now?" (5단어)
  • 기본 RNN은 "단어 하나 들어오면 단어 하나 나간다" 식이라 이런 번역을 못 합니다.

2. Seq2Seq (Sequence to Sequence) ★#

  • Google, 2014 발표 (논문: arxiv.org/abs/1409.3215)
  • 이름 뜻: 시퀀스(문장)를 받아서 → 시퀀스(문장)를 내보낸다
  • RNN의 한계 (가변 길이에 동작하지 않음) 를 해결
  • 방법: 두 개의 LSTM 네트워크를 이용한 Encoder / Decoder 구조
  • Input: LSTM/GRU 기반 구조로 단어 시퀀스를 입력
  • Output: 입력에 적합한 길이의 시퀀스를 출력

구조 — "다 듣고, 정리하고, 말하기"#

            Encoder (인코더)                         Decoder (디코더)
   ┌──────────────────────────┐            ┌──────────────────────────────┐
   I → am → a → student  ──→  [Context Vector]  ──→  <sos> → je → suis → étudiant → <eos>
   (RNN 셀이 한 단어씩 읽음)    (요약 벡터 1개)       (한 단어씩 출력)
Encoder (인코더)
입력 문장의 모든 단어를 순차적으로 입력받은 후, 마지막에 모든 단어 정보를 압축해서 하나의 벡터로 만듦 (encoding) → 이게 Context vector
Context vector (문맥 벡터)
입력 문장 전체의 의미가 압축된 벡터 1개
Decoder (디코더)
Context vector를 받아서 번역된 단어를 한 개씩 순차적으로 출력 (decoding) → 이렇게 해서 서로 다른 길이의 입/출력에 대응

특수 토큰

토큰 뜻 역할
<sos> start of sentence "이제 말 시작해" 신호. 디코더의 첫 입력
<eos> end of sentence "말 끝났다" 신호. 이게 나오면 출력 종료

참고

비유: 동시통역사가 아니라 순차통역사 1. 연사의 말을 끝까지 다 듣고 (Encoder) 2. 머릿속에 "이 사람이 한 말의 요지"를 하나로 정리한 뒤 (Context Vector) 3. 그 요지를 보고 다른 언어로 한 단어씩 말함 (Decoder) — "시작"(<sos>)부터 "끝"(<eos>)까지

디코더는 말할 때 자기가 방금 한 말을 다음 입력으로 씁니다: <sos> → je → (je를 보고) suis → (suis를 보고) étudiant → <eos>

시험 포인트

Encoder / Context Vector / Decoder 각각의 역할 - Encoder: 입력 단어를 순차적으로 받아 하나의 벡터로 압축 - Context Vector: 입력 문장 전체 정보가 압축된 고정 크기 벡터 - Decoder: Context Vector를 받아 출력 단어를 하나씩 순차적으로 생성 → 입출력 길이가 달라도 대응 가능

3. Transformer의 등장 ★★#

  • 논문: "Attention Is All You Need" (2017), arxiv.org/abs/1706.03762
  • 제목 뜻: "Attention만 있으면 된다" → RNN 없이 Attention이라는 방법만으로 만들었다는 자신감
  • Seq2Seq(Encoder-Decoder) 구조를 따르면서도 Attention만으로 구현된 모델
  • RNN을 사용하지 않고 Encoder-Decoder 구조로만 설계 → RNN보다 우수한 성능
  • 아직까지도 다양한 분야에서 사용되는 범용적 모델 (GPT, Claude, Gemini 전부 Transformer 기반)

기존 Seq2Seq / RNN 계열은 시간에 의존적인 입력 sequence에 따라 hidden state를 생성하여 입력을 처리하는 구조 (= 한 단어씩 순서대로 메모장을 갱신하는 방식) 였고, 이 방식에서 고질적인 한계 3가지가 생겼습니다.

Seq2Seq / RNN의 고질적 한계 3가지 ★★#

시험 포인트

Transformer가 무엇을 해결했는가 — 거의 반드시 나옵니다. 3개를 세트로 외우세요.

  1. 고정된 크기의 벡터에 모든 정보 압축 → 정보 손실 발생
  2. Vanishing Gradient Problem (기울기 소실)
  3. 입력의 순차적 처리 → 병렬화 불가능

한계 ① 고정 크기 벡터에 모든 정보 압축 → 정보 손실#

  • 문장이 3단어든 300단어든, Context Vector는 똑같은 크기 1개
  • 긴 문장일수록 다 못 담고 흘려버림

참고

비유: 영화 한 편을 "한 줄 평"으로 요약하기 3분짜리 광고는 한 줄로 요약해도 괜찮지만, 3시간짜리 영화를 한 줄로 요약하면 대부분의 내용을 잃습니다. 그런데 디코더는 그 한 줄만 보고 번역해야 합니다.

한계 ② Vanishing Gradient Problem (기울기 소실)#

참고

비유: 귓속말 전달 게임 30명이 줄 서서 귓속말을 전하면 뒤로 갈수록 말이 뭉개져서 처음 말이 사라집니다.

RNN은 학습할 때 "여기 틀렸어!"라는 수정 신호(gradient, 기울기) 를 문장 뒤에서 앞으로 전달합니다. 단어를 하나 거칠 때마다 신호가 조금씩 약해져서, 문장 앞부분에 도착할 땐 거의 0이 됩니다. → 긴 문장의 앞부분을 제대로 배우지 못합니다. (자세히: 0장 8절)

한계 ③ 순차적 처리 → 병렬화 불가능#

  • RNN은 1번째 단어를 처리해야 2번째로, 2번째를 처리해야 3번째로 갈 수 있음
  • 동시에 여러 단어를 처리(병렬화)할 수 없음 → 느림

참고

병렬화 = 여러 일을 동시에 하는 것. 비유: 시험지 100장 채점 - 순차 처리: 선생님 1명이 1장씩 → 100번 반복 (느림) - 병렬 처리: 선생님 100명이 1장씩 동시에 → 1번에 끝 (빠름)

GPU(그래픽카드)는 동시에 수천 개 계산을 잘하는 장치인데, RNN은 순서를 기다려야 해서 GPU를 제대로 못 씁니다. Transformer는 문장 전체를 한꺼번에 넣으니까 GPU를 100% 활용할 수 있습니다.

4. Transformer 모델 구조 ★#

큰 틀 — 여전히 Encoder-Decoder#

  • Seq2Seq처럼 Encoder-Decoder 구조를 사용
  • <sos> 토큰을 입력으로 받아 <eos> 토큰이 나올 때까지 연산 수행
  • RNN은 사용되지 않았지만 encoder-decoder의 구조는 유지
 I  am  a  student              <sos>  je  suis  étudiant
 ↓   ↓  ↓    ↓                    ↓     ↓    ↓      ↓
[Embedding layer]               [Embedding layer]
 ↓                                ↓
[    Encoders    ]  ─────────→  [    Decoders    ]
                                  ↓
                         je  suis  étudiant  <eos>

Transformer의 입력 — Embedding + Positional Encoding ★#

중요

Transformer는 단어의 embedding vector를 그대로 입력받지 않습니다. Embedding vector에서 "조정된 값" 을 입력으로 활용합니다 = Embedding + Positional Encoding(위치 정보)

(슬라이드: "단순히 각 단어의 embedding vector를 입력으로 받지 않음 (RNN의 고유한 특성)")

왜 위치 정보를 따로 더해야 하나?

  • RNN은 순서대로 한 단어씩 넣으니까, 모델이 자동으로 순서를 압니다.
  • Transformer는 모든 단어를 한꺼번에 넣습니다 (병렬화를 위해).
  • 그러면 모델 입장에선 "I am a student"와 "student a am I"가 똑같아 보입니다! 그냥 단어 4개가 든 봉지일 뿐이니까요.
  • 그래서 각 단어에 "너는 1번째, 너는 2번째…" 라는 위치 표시(Positional Encoding) 를 숫자로 더해 줍니다.

참고

비유: 단체 사진 찍을 때 번호표 달기 학생들을 한꺼번에 운동장에 풀어 놓으면 원래 줄 순서를 모릅니다. 그래서 각자 가슴에 번호표(1번, 2번, 3번…) 를 달아 줍니다. 한꺼번에 모여 있어도 번호표를 보면 순서를 알 수 있죠.

입력 = 단어의 의미 (Embedding)  +  단어의 위치 (Positional Encoding)
        "student"라는 뜻              "4번째 자리"

내부 구성요소#

슬라이드 구조도를 표로 풀면:

구성 요소 위치 쉬운 설명
Embedding + Positional Encoding 인코더·디코더 맨 아래 단어 의미 + 위치 번호표
Multi-head Self-Attention 인코더 Encoder Self-Attention: 입력 문장 안의 단어들이 서로를 참고
Masked Multi-head Self-Attention 디코더 Masked Decoder Self-Attention: 아직 안 쓴 뒤쪽 단어는 가리고(mask) 앞쪽만 참고
Multi-head Attention (두 번째) 디코더 Encoder-Decoder Attention: 디코더가 인코더의 결과를 참고
Position-wise FFNN 인코더·디코더 각 단어 위치마다 따로 적용하는 일반 신경망 (Feed-Forward Neural Network)
Add & Norm 각 단계 뒤 Add: 원래 입력을 결과에 다시 더해줌 / Norm: 숫자 크기를 고르게 맞춤
Dense → Softmax 디코더 맨 위 다음 단어 후보들의 점수 → 확률로 변환

참고

Add & Norm 쉽게: - Add (잔차 연결): 처리한 결과에 처리 전 원본을 다시 더해 줍니다. 처리하다 중요한 정보를 잃어도 원본이 남아 있게 하는 안전장치입니다. (기울기 소실도 줄여 줌) - Norm (정규화): 숫자들이 너무 커지거나 작아지지 않게 크기를 고르게 맞춥니다.

FFNN 쉽게: Attention이 "누구를 참고할지" 정했다면, FFNN은 그렇게 모은 정보를 한 번 더 가공하는 단계입니다.

Softmax 쉽게: 후보 단어 점수(고양이 2.0점, 강아지 1.0점…)를 합이 100%인 확률(고양이 66%, 강아지 24%…)로 바꿉니다. (0장 9절)

5. Attention이란? ★★#

Transformer의 핵심 아이디어입니다. 시험에서 깊은 수식은 안 나오지만 개념은 꼭 알아야 합니다.

Attention = "중요한 데에 집중하기"#

참고

다음 문장을 보세요. "동물이 길을 건너지 않았다. 왜냐하면 그것이 너무 피곤했기 때문이다."

여기서 "그것" 은 뭘까요? 사람은 바로 "동물" 이라는 걸 압니다. "길"이 피곤할 리는 없으니까요.

컴퓨터도 "그것"을 이해하려면 문장의 다른 단어들을 둘러보면서 "누가 나랑 관련 있지?" 를 따져야 합니다. - "동물" ↔ "그것": 관련도 높음 ★★★ - "길" ↔ "그것": 관련도 낮음 ★ - "건너지" ↔ "그것": 관련도 낮음 ★

이렇게 관련도를 점수로 계산해서, 중요한 단어에 더 집중하는 것이 Attention입니다.

Self-Attention = 같은 문장 안에서 서로 참고하기#

  • Self(자기 자신) = 같은 문장 안의 단어들끼리 Attention
  • 모든 단어가 다른 모든 단어와의 관련도를 한 번에 계산
  • → 문장이 길어도 1번째 단어와 100번째 단어가 직접 연결됨 (RNN처럼 귓속말로 전달할 필요 없음)

Query / Key / Value — Attention 계산에 쓰는 3가지#

참고

비유: 도서관에서 책 찾기

이름 도서관 비유 Attention에서
Query (Q) 내가 찾는 것: "고양이 키우는 법" 지금 이 단어가 알고 싶은 것
Key (K) 각 책 등에 붙은 제목표 각 단어가 내건 "나는 이런 단어야" 이름표
Value (V) 책 안의 실제 내용 각 단어가 가진 실제 정보
  1. 내 질문(Q)과 각 책 제목표(K)를 비교해서 점수를 냄 → Dot product
  2. 점수를 적당히 조절하고, 볼 수 없는 건 가림 → Scaling · Mask
  3. 점수를 확률(비율)로 변환 → Softmax
  4. 그 비율대로 책 내용(V)을 섞어서 가져옴 → Out

예: "고양이 책" 70% + "애완동물 책" 25% + "요리책" 5% 비율로 내용을 섞어 읽는 것.

슬라이드의 계산 흐름:

Query · Key  →  Dot product  →  Scaling · Mask  →  Softmax · Dropout  →  × Value  →  Out
  (비교)          (점수)          (조절·가리기)        (확률로)                    (섞어서 결과)
  • Dot product (내적): 두 벡터가 얼마나 비슷한지 점수 내는 계산 (코사인 유사도의 친척)
  • Dropout: 학습할 때 일부 연결을 일부러 랜덤하게 끊어서 과적합(외워버리기)을 막는 기법

Multi-head = 여러 관점으로 동시에 보기#

  • Attention 계산을 한 번이 아니라 여러 번(여러 head) 동시에 수행
  • 각 head가 서로 다른 관점으로 관련도를 봄

참고

비유: 영화 한 편을 여러 평론가가 동시에 리뷰 - 1번 평론가(head): 문법 관점 — "이 동사의 주어는 누구지?" - 2번 평론가(head): 의미 관점 — "'그것'이 가리키는 건?" - 3번 평론가(head): 감정 관점 — "긍정적인 말인가?"

여러 관점을 합치면 더 풍부하게 이해할 수 있습니다.

Masked = 미래 단어 가리기#

  • 디코더는 문장을 왼쪽부터 한 단어씩 생성합니다.
  • 학습할 때 정답 문장 전체를 넣어 주는데, 뒤에 올 단어를 미리 보면 커닝이 됩니다.
  • 그래서 아직 생성 안 한 뒤쪽 단어는 가려서(mask) 못 보게 합니다.

참고

비유: 받아쓰기 시험에서 다음 문장이 적힌 부분을 손으로 가리고 지금까지 쓴 것만 보고 다음 단어를 쓰게 하는 것.

6. NLP 패러다임의 변화 ★#

  • 기계는 강력한 인공지능을 장착하지 않는 이상, 인간의 언어 형태로 이해하고 소통하는 것이 불가능

Language Modeling의 목표 ★#

Language Modeling (언어 모델링)
단어 시퀀스의 생성 가능성을 모델링하여 미래 토큰의 확률을 예측하는 것

쉽게: "지금까지 나온 단어를 보고, 다음 단어가 뭘지 확률로 맞히는 것."

"오늘 날씨가 정말 ___"

  좋다   : 45%
  덥다   : 30%
  춥다   : 15%
  바나나 : 0.001%

시험 포인트

Language Modeling 정의 그대로 외우기: "단어 시퀀스의 생성 가능성을 모델링하여 미래 토큰의 확률을 예측" 수식: P(S) = P(w₁) × P(w₂|w₁) × P(w₃|w₁,w₂) × … (0장 4절)

History of Language Model — SLM → NLM → PLM → LLM ★★#

언어 모델 발전 4단계. 시기 / 핵심 기술 / 대표 모델 / 특징을 표로 묻기 좋습니다. 슬라이드 부제: "더 자연스러운 언어 이해와 생성으로, 인간과 AI의 가능성을 확장해온 여정"

용어 풀이

용어 쉬운 뜻
N-gram 앞의 N−1개 단어만 보고 다음 단어를 맞히는 방식. 예: 2-gram은 바로 앞 1단어만 봄 ("오늘" 다음엔 "날씨"가 자주 나왔으니 "날씨")
MLE (최대우도추정) "데이터에서 가장 자주 나온 걸 정답으로 추정"하는 통계 방법. "오늘 날씨" 다음에 "좋다"가 100번 중 45번 나왔으면 확률 45%
Kneser-Ney Smoothing 데이터에 한 번도 안 나온 조합도 확률 0이 되지 않게 살짝 보정해 주는 기법
분산 표현 = Dense representation (2장). 의미를 여러 숫자에 나눠 담는 표현
전이학습 한 곳에서 배운 지식을 다른 일에 옮겨 쓰는 것 (영어 배운 사람이 독일어를 더 빨리 배우듯)
T5 구글이 만든 PLM. 모든 작업을 "글 → 글" 변환으로 통일한 모델
멀티모달 글뿐 아니라 이미지·소리까지 다루는 것

참고

각 단계 한계가 다음 단계를 낳는 흐름 - SLM: 바로 앞 몇 단어만 봄 → 맥락 이해 못 함 → 신경망으로 해결 (NLM) - NLM: RNN이라 기울기 소실 → Transformer로 해결 (PLM) - PLM: 작업마다 파인튜닝 필요 → 거대화 + 프롬프트로 해결 (LLM) - LLM: 너무 강력해서 안전성·정렬이 새 과제가 됨 → 5장 Alignment Tuning

시험 포인트

핵심 전환 (슬라이드 별표 문장) "대규모 사전학습 + 다운스트림 작업 파인튜닝이 표준 패러다임이 되었다" 결과: ✓ 성능 향상 ✓ 적용 범위 확대 ✓ 사용자 경험 혁신 ✓ 산업 전반의 AI 전환 가속화

참고

2장의 "임베딩 기법의 발전 3단계" 와 같은 이야기입니다. 통계 기반 (SLM, One-hot, TF-IDF) → 딥러닝 기반 (NLM, Word2Vec) → 전이학습 기반 (PLM/LLM, BERT, GPT)

7. Pre-trained Language Model (PLM) ★#

많은 양의 텍스트 데이터를 활용해 일반적인 수준의 '언어 이해'가 가능하도록 사전 학습을 시킨 언어 모델

1. Pre-training (사전학습)              2. Fine-tuning (미세조정)
   위키피디아 등 대량의 글(Corpus)          특정 과제 데이터 (Downstream task)
   ↓                                       예: KorQuAD(한국어 질의응답),
   BERT가 일반적인 언어 능력 습득              네이버 영화 리뷰 감정 분류
                                           ↓
                                           그 과제를 잘하는 BERT
  • 사전 학습된 모델을 텍스트 분류, 생성, 번역 등 다양한 downstream task에서 fine-tuning하여 사용 가능
  • task마다 end-to-end로 따로 학습하는 방식에 비해 여러 자연어 처리 task의 성능을 비약적으로 끌어올림

참고

비유: 대학 교양 → 전공 - Pre-training = 대학 1~2학년 교양 수업. 국어, 영어, 상식 등 두루두루 배움 (책을 엄청 많이 읽음) - Fine-tuning = 3~4학년 전공 수업. 교양을 바탕으로 특정 분야를 집중적으로 배움

교양을 탄탄히 쌓은 학생이 어떤 전공이든 빨리 배우죠. 처음부터 전공만 파는 것(end-to-end)보다 훨씬 효율적입니다.

Downstream task = 사전학습 "다음에(아래 흐름에서)" 하는 실제 목표 과제 End-to-end = 처음부터 끝까지 그 과제 하나만을 위해 모델을 새로 학습하는 방식

중요

Pre-training vs Fine-tuning (4·5장에서 계속 나옴)

Pre-training Fine-tuning
데이터 정답 없는 대량의 글 정답(label)이 있는 특정 과제 데이터
목적 일반적 언어 능력 특정 과제에 맞추기
학습 방식 비지도 지도
