4. LLM과 GPT 시리즈#

이 장의 한 줄 요약#

Transformer를 엄청나게 크게 만들었더니(LLM), 따로 가르치지 않아도 예시만 보여주면 알아서 하는 능력이 생겼다.

GPT가 1 → 2 → 3으로 가면서 "점점 덜 가르쳐도 되게" 바뀐 과정이 이 장의 전부입니다.

GPT-1 (2018): 사전학습 + 과제마다 따로 가르치기(Fine-tuning)      ← 매번 가르쳐야 함
GPT-2 (2019): 사전학습만으로 여러 과제를! (Fine-tuning 없애보자)    ← 덜 가르쳐도 됨
GPT-3 (2020): 프롬프트에 예시 몇 개만 보여주면 끝 (In-context)      ← 안 가르쳐도 됨
ChatGPT (2022): 말 잘 듣게 다듬기 (5장 Adaptation Tuning)

1. LLM이란? ★#

LLM (Large Language Model, 거대 언어 모델)
방대한 텍스트 데이터로 학습된 수천 억 개의 파라미터를 가진 Transformer 기반의 Language Model
  • 언어를 이해하고 복잡한 과업을 수행하는 데 강력한 능력

시험 포인트

정의에서 3가지 요소를 빠뜨리지 마세요. ① 방대한 텍스트 데이터로 학습 ② 수천 억 개의 파라미터 ③ Transformer 기반 Language Model

참고

파라미터 = 모델 안의 다이얼 (0장 7절). 수천억 개의 다이얼을 인터넷 글로 맞춰 놓은 거대한 "다음 단어 맞히기 기계"가 LLM입니다.

Emergent Abilities (창발적 능력) ★★#

중요

슬라이드에서 큰 글씨로 강조한 문장: "Emergent Abilities: 기존 PLM과 구별되는 LLM의 가장 큰 특징"

"PLM과 LLM의 차이는?" → 정답은 "크기가 크다"가 아니라 "Emergent Abilities가 있다" 입니다.

Emergent(창발적) = 작을 땐 전혀 없다가, 어느 크기를 넘으면 갑자기 생겨나는 것.

참고

비유: 물이 끓는 것 물을 1도, 2도… 99도까지 데워도 그냥 뜨거운 물입니다. 그런데 100도를 넘는 순간 갑자기 끓기 시작하죠. LLM도 그렇습니다. 모델을 조금씩 키워도 그저 그렇다가, 어떤 크기를 넘으면 갑자기 새로운 능력이 생깁니다. 그래서 "더 크게 만들자"는 흐름이 생겼습니다.

LLM의 Emergent Abilities 3가지:

능력 쉬운 뜻 예
In-context Learning 따로 학습 안 시켜도, 프롬프트 안의 예시만 보고 과제를 해냄 "개→dog, 고양이→cat, 사자→?" 하면 "lion"
Instruction Following 지시(명령) 를 알아듣고 그대로 따름 "3줄로 요약해줘" 하면 3줄로 요약
Step-by-Step Reasoning 단계별로 생각해서 복잡한 문제를 풂 수학 문제를 풀이 과정과 함께 풀기 (6장 CoT)

LLM을 쓰는 이점 (Benefits of using LLMs) ★#

  1. 사전 학습된 단일 모델이 여러 task에 사용될 수 있음 - 하나의 LLM을 번역, 문장 생성, 문장 분류, QA(질의응답) 등 다양한 task에 사용 가능 - (예전엔 번역 모델, 요약 모델을 따로 만들었음)
  2. Fine-tuning을 위한 특정 task의 데이터가 많이 필요하지 않음 - Few-shot 혹은 zero-shot setting에서도 우수한 성능 (예시 몇 개, 혹은 0개로도 잘함)
  3. 학습 데이터와 모델의 파라미터를 증가시킴으로써 성능을 지속적으로 향상시킬 수 있음 - 키우면 키울수록 좋아짐

2. GPT란?#

GPT: Generative Pre-trained Transformer

글자 뜻
Generative 생성하는 (글을 만들어 냄)
Pre-trained 미리 학습된 (사전학습)
Transformer Transformer 구조 기반
  • Transformer의 생성형 Decoder 구조 기반의 Autoregressive 모델
Autoregressive (자기회귀)
주어진 입력의 일부를 사용하여 이후에 오는 부분을 예측. 즉 주어진 연속된 단어의 다음 단어를 맞추는 방식

참고

Autoregressive를 쉽게: "끝말잇기처럼 자기가 쓴 말을 보고 다음 말 쓰기"

입력: "오늘 날씨가"
  → 다음 단어 예측: "정말"       → "오늘 날씨가 정말"
  → 다음 단어 예측: "좋네요"     → "오늘 날씨가 정말 좋네요"
  → 다음 단어 예측: <끝>

자기가 방금 만든 단어를 다시 입력으로 넣어서 다음 단어를 만듭니다. "자기(auto)를 다시 보며(regressive)" 라는 뜻이에요.

중요

GPT = Transformer의 Decoder만 사용 (BERT는 Encoder 계열) → 그래서 GPT는 왼쪽에서 오른쪽으로만 읽는 단방향 모델입니다. (3장 Paradigms 참고)

3. GPT-1 (2018) ★#

논문: "Improving Language Understanding by Generative Pre-Training"

  • 비지도 사전학습과 지도 미세조정을 조합한 NLP에 대한 '준지도학습' 제시
  • 다양한 작업에 쉽게 전이 가능한 보편적인 표현 학습
  • 최소한의 모델 구조 변화를 통해 목적에 맞게 전이학습 가능

참고

준지도학습 = 비지도(정답 없음) + 지도(정답 있음) 를 섞은 것. 1단계는 정답 없는 대량의 글로, 2단계는 정답 있는 소량의 데이터로 → 둘을 섞었으니 "준(準)지도". (0장 11절: 지도/비지도/강화 학습)

GPT Framework (2단계) ★#

단계 이름 하는 일 데이터
Step 1 Unsupervised Pre-Training (비지도 사전학습) 대량의 말뭉치로 대용량의 언어모델 학습. 지금까지의 토큰 순서를 기반으로 다음 토큰이 나타날 확률 추정 정답 없는 대량의 글
Step 2 Supervised Fine-tuning (지도 미세조정) Labeled Data를 사용하여 목표 Task에 맞게 미세조정 정답 있는 특정 과제 데이터
  • 말뭉치(코퍼스, corpus) = 학습에 쓰는 대량의 글 모음
  • Labeled Data = 정답(label)이 붙어 있는 데이터 (예: "이 영화 최고!" → 긍정)

Contribution of GPT-1 (GPT-1의 공헌)#

  • GPT-Series 모델의 핵심 구조 설정, 다음 단어 예측을 위한 기본 원칙 확립
  • Generative Pre-Training이 모델의 일반화 성능을 높이는 데 효과적임을 확인
  • 사전학습을 통해 다양한 NLP Tasks에서 Zero-shot 성능 향상을 입증

4. GPT-2 (2019) ★#

논문: "Language Models are Unsupervised Multitask Learners" (제목 뜻: "언어 모델은 비지도로 여러 과제를 배우는 학습자다")

  • GPT-1에서 더 큰 데이터셋 & 더 많은 파라미터 학습을 통해 더 강력한 언어모델 학습
  • 동일한 Unsupervised Model을 활용하여 Multiple Tasks 학습
  • 목표: 모델이 주어진 입력 문장들을 통해 적합한 Task를 유추하고 적절한 답을 내는 것

GPT-2 Architecture#

  • GPT-1보다 10배 많은 1.5 Billion(15억) 개의 Parameters
  • GPT-2 내부 버전에 따라 Parameter와 Layer 개수를 다르게 지정 (작은 버전~큰 버전)

Task Conditioning ★★ (GPT-1과의 핵심 차이)#

시험 포인트

목적함수(Objective) 비교 — 전형적인 출제 포인트

  • GPT-1: P(Output | Input)
  • GPT-2: P(Output | Input, Task) → 다른 Task에 대해 동일한 Input임에도 다른 Output 생성

수식 읽는 법 (0장 4절)

  • P(Output | Input) = "입력이 주어졌을 때, 출력이 나올 확률"
  • P(Output | Input, Task) = "입력과 '무슨 과제인지'가 함께 주어졌을 때, 출력이 나올 확률"

참고

예시로 이해하기

입력: "I love you"

Task (과제) Output
"한국어로 번역해" "사랑해"
"감정을 분류해" "긍정"
"단어 수를 세" "3"

똑같은 입력인데 과제에 따라 답이 다르죠? GPT-2는 과제까지 조건으로 받아서 하나의 모델로 이걸 다 해냅니다. GPT-1은 과제마다 따로 fine-tuning한 모델이 필요했습니다.

Zero-Shot Learning & Zero-Shot Task Transfer#

  • GPT-1: Task의 종류에 따라 Input을 Ordered Sequence로 변환해 줘야 함
  • (사람이 과제별로 입력 형식을 일일이 맞춰서 넣어 줌)
  • GPT-2: 모델이 주어진 Task의 특성을 이해하고 알아서 답을 내릴 것으로 예상
  • (형식 안 맞춰도, 모델이 "아 이건 번역이구나" 알아챔)

참고

Zero-shot = 예시를 0개 보여주고 시키는 것. "처음 보는 문제를 바로 풀기"

GPT-2의 결론#

  • Parameter의 개수가 가장 많은 모델이 모든 Downstream Task에서 가장 높은 성능
  • 더 큰 Dataset & 더 많은 Parameters로 더 강력한 언어모델 학습 가능성 확인
  • → 즉, 더 큰 Language Model을 구축하자!!

5. GPT-3 (2020) ★★#

논문: "Language Models are Few-shot Learners" (제목 뜻: "언어 모델은 예시 몇 개로 배우는 학습자다")

  • 1,750억 개의 파라미터를 가지며, 미세조정(Fine-tuning)이 생략된 언어 모델
  • Few-shot & Zero-shot 방식으로 LLM을 활용하는 In-context Learning을 공식적으로 도입

GPT-3 Architecture#

  • 더 많은 데이터, 더 깊은 구조로, 더 오랫동안 학습
  • GPT-2와 거의 유사한 구조를 가지며 우수한 성능 도출 (구조는 비슷, 크기만 확 키움)

왜 Fine-tuning을 없앴나?#

Overall Process of Language Model (기존 방식의 문제)

  • 기존 사전 학습된 언어모델의 구조는 Task-agnostic(과제와 무관, 범용)임에도 불구하고
  • 미세조정 단계에서는 여전히 해당 Task의 Labeled Dataset이 필요
  • 즉 Task-specific한 Dataset을 바탕으로 Task-specific 미세조정을 수행해야 했음

참고

Task-agnostic = "과제를 가리지 않는", 범용의 Task-specific = "특정 과제 전용의"

모델 자체는 범용인데, 쓰려고 할 때마다 그 과제 전용 정답 데이터를 만들어서 또 학습시켜야 했다는 모순입니다.

Limitation of Fine-tuning (Fine-tuning의 한계) ★★#

시험 포인트

3가지 — 서술형으로 나오기 좋습니다.

  1. 새로운 Task에 대한 Task별 Labeled Dataset이 필요
  2. 미세조정을 거쳐 작은 Task의 분포를 따르면 과적합이 발생하여, 분포 밖 Dataset에 대해 일반화 성능을 잃을 수 있음
  3. 사람과 같이 적은 샘플로도 Task를 수행하는 능력 필요

쉽게 풀기

  1. 정답 데이터 만들기가 힘들다: 새 과제마다 수천~수만 개의 "문제+정답"을 사람이 만들어야 함 → 돈·시간 많이 듦
  2. 과적합 위험: 좁은 데이터로 세게 가르치면 그 데이터만 잘하고 처음 보는 데이터엔 약해짐

참고

과적합 비유: 기출문제만 외운 학생 (0장 12절) 기출 100문제만 달달 외우면 기출은 100점인데, 새로운 유형이 나오면 못 풉니다. 분포 밖(out-of-distribution) = 학습할 때 본 것과 다른 종류의 데이터

  1. 사람은 그렇게 안 배운다: 사람은 예시 2~3개만 보면 "아 이런 거구나" 하고 따라 하죠. AI도 그래야 한다는 것.

GPT-3: No Fine-Tuning Required#

  • Labeled Dataset이 필요한 미세조정 단계를 제외
  • 미세조정 없이 사전학습만으로 동작하는 모델 구축
  • 이를 가능하게 한 두 축: → In-context Learning + → Large Capacity (거대한 모델 용량)

6. In-context Learning ★★#

In-context Learning
프롬프트의 맥락적 의미(In-context)를 모델이 이해하고, 이에 대한 답변을 생성
  • 사전학습이나 미세조정처럼 모델을 업데이트하지 않고, 별도의 모델 학습 과정 없음
  • Demo Context 구성을 위한 소수의 예시 필요

참고

비유: 새로 온 알바생에게 일 가르치기

  • Fine-tuning 방식: 알바생을 2주간 교육센터에 보내서 재교육 → 알바생의 머리 자체가 바뀜
  • In-context Learning 방식: 일하기 직전에 "이건 이렇게, 저건 저렇게 해" 하고 예시 2~3개 보여줌 → 알바생 머리는 그대로, 그 자리에서 보고 따라 함

In-context = "문맥(context) 안에서" 배운다 = 프롬프트 안에 넣어 준 예시를 보고 그 자리에서 배운다는 뜻.

중요

In-context Learning의 핵심: 모델 파라미터가 바뀌지 않는다!

Fine-tuning In-context Learning
모델 파라미터 바뀜 (재학습) 안 바뀜
필요한 것 정답 데이터 수천 개 + 학습 시간 프롬프트 속 예시 몇 개
비유 교육센터 보내기 일 시작 전에 예시 보여주기

Few-shot / One-shot / Zero-shot ★#

shot = 예시(시범) 의 개수라고 생각하면 됩니다.

구분 슬라이드 정의 예시 개수
Few-shot 모델에게 Task 설명 + Model의 Context Window k에 맞는 예제 제공 (Limited Labeled Dataset) 몇 개
One-shot 모델에게 하나의 예제만 제공 (One Labeled Example) 1개
Zero-shot 모델에게 예시 제공 없음, 사전 지식만으로 예측 (No Labeled Example) 0개

예시로 보기 (영어 → 프랑스어 번역)

[Zero-shot]
Translate English to French:
cheese =>

[One-shot]
Translate English to French:
sea otter => loutre de mer
cheese =>

[Few-shot]
Translate English to French:
sea otter => loutre de mer
peppermint => menthe poivrée
plush giraffe => girafe peluche
cheese =>

참고

Context Window k = 모델이 한 번에 읽을 수 있는 분량. 여기에 맞게 예시를 넣을 수 있는 만큼 넣는다는 뜻.

관찰된 성질 (슬라이드)

  • Context Window k가 증가할수록 성능 향상 확인 (예시를 많이 넣을수록 잘함)
  • 모델이 커질수록 In-context Learning의 효율 증가 (큰 모델일수록 예시를 더 잘 활용)
  • Task에 대한 Prompt의 도움 확인 (과제 설명을 잘 써주면 도움 됨)

시험 포인트

Zero / One / Few-shot의 정의와 예시 개수(0 / 1 / 몇 개) 는 단답 단골입니다. "모델을 업데이트하지 않는다" 는 In-context Learning의 특징과 함께 쓰면 완벽합니다.

7. GPT-3의 한계와 영향#

Limitation of GPT-3 ★#

  1. 긴 문장 구성에 일관성을 잃고 Text Sequence를 반복하는 경향 - 글이 길어지면 앞뒤가 안 맞거나 같은 말을 되풀이함
  2. 모델의 단방향성으로 인해 자연어 추론과 같은 Task를 잘 해내지 못함 - → 유사한 규모의 양방향 모델 고려 가능
  3. 각 Token에 동일한 가중치가 부여되므로 목표 지향적 예측 개념 결여 - 학습할 때 모든 단어를 똑같이 중요하게 다룸 → "이 단어가 정답의 핵심" 같은 개념이 없음

참고

단방향성이 왜 추론에 약한가? GPT는 왼쪽→오른쪽으로만 읽습니다 (Decoder 기반). "그 사과는 ___ 해서 버렸다. 썩었기 때문이다." 같은 문장에서 빈칸을 채우려면 뒤의 "썩었기 때문이다" 를 봐야 하는데, 단방향 모델은 뒤를 못 봅니다. BERT 같은 양방향 모델은 문장 앞뒤를 다 보므로 이런 자연어 추론(NLI) 에 유리합니다.

Broader Impacts of GPT-3 (사회적 영향)#

영향 내용
언어모델의 오용 가짜뉴스, 스팸, 피싱 등에 악용
공정성, 편향성 및 대표성 인터넷에서 수집한 데이터를 기반으로 하므로 그곳에 존재하는 편견과 편향을 그대로 학습 → 성별, 민족, 인종, 종교에 대한 편견과 선입견 존재
에너지 소비 모델 학습에 상당한 자원 소비, 하지만 훈련 후에는 효율적 → 한 번 훈련에 약 50억 소요, Tesla V100 하나로 355년 소요

참고

Tesla V100 = 엔비디아의 AI 계산용 그래픽카드. 이걸 1대만 쓰면 GPT-3 학습에 355년 걸린다는 뜻 → 실제로는 수천 대를 동시에 씁니다.

8. GPT 시리즈 정리표 ★★★#

시험 포인트

이 장의 핵심 표입니다. 빈칸 채우기로 나와도 전부 쓸 수 있어야 합니다.

구분 GPT-1 GPT-2 GPT-3
출현 2018 2019 2020
핵심 개념 PLM(Pretrained LM) + SFT 거대 언어모델 (Generative LM) Few-shot / Zero-shot LLM
훈련 방식 1. Unsupervised Pre-trained
2. DownStream Supervised Fine-Tuning(SFT)		 Pre-trained만으로 여러 작업 수행하게끔!!
→ SFT 과정을 없애자		 프롬프트만으로 대부분 작업 수행 (In-context learning)
입력 문장 → 다음 단어 예측 동일 "task instruction + examples + input"
혁신 포인트 BERT보다 먼저 나온 Transformer LM 멀티태스킹 가능해짐 지능적 프롬프트 이해
파라미터 117M (1억 1700만) 1.5B (15억) 175B (1750억)

참고

외우는 요령: "가르침이 점점 줄어든다" - GPT-1: 사전학습 + 가르침(SFT) - GPT-2: 사전학습만 (가르침 없애자) - GPT-3: 사전학습 + 예시만 보여주기

파라미터는 대략 10배씩: 1억 → 15억 → 1750억 (GPT-2→3은 100배 이상) SFT = Supervised Fine-Tuning (지도 미세조정)

9. ChatGPT ★#

  • 2022년 11월에 OpenAI에서 출시한 대화형 인공지능 챗봇
  • GPT-3가 개선된 GPT-3.5 및 GPT-4 모델 기반
  • InstructGPT와 유사한 방식으로 학습되었지만, 대화에 최적화 & 안전성 강화

중요

GPT-3 → ChatGPT의 결정적 변화는 "모델을 더 키운 것"이 아니라 "Adaptation Tuning" (5장: Instruction Tuning + RLHF) 쉽게 말해 "더 똑똑해진 것"이 아니라 "말을 잘 듣게 된 것" 입니다.

ChatGPT History — GPT 시리즈의 기술적 진화#

시기 모델 파라미터 핵심 변화 특징
2018 GPT-1 1.17억 사전학습 + 미세조정 패러다임 시작 디코더 기반 트랜스포머로 다음 단어 예측. 대규모 텍스트 사전학습 후 소량 데이터 미세조정 가능성 입증
2019 GPT-2 15억 Zero-shot / Few-shot 가능성 확대 모델과 데이터 규모 확대로 번역·요약·문답을 프롬프트만으로 수행. 범용 언어 모델의 잠재력을 보여줌
2020–2022 GPT-3 / GPT-3.5 1,750억 In-Context Learning 성숙 + RLHF 도입 코딩·글쓰기·추론 능력이 비약적으로 향상. ChatGPT 출시로 대중화와 AI 혁명을 견인
2023–2024 GPT-4 / GPT-4o 수조 개 추정 · MoE 멀티모달 + 네이티브 옴니 텍스트를 넘어 이미지·음성까지 처리, 실시간 상호작용과 향상된 추론 능력으로 새로운 사용자 경험 제공
2025–2026 GPT-5 시리즈 GPT-5 / 5.5 / 5.6 추론 모드 성숙 + 자율 에이전트화 긴 컨텍스트, 도구 사용, 웹 탐색, 업무 자동화 강화. AI Co-worker로서의 활용성 확대
2026 GPT-6 Astra 최신 공개 모델 고도 안전성 + 빠른 컴퓨터 사용 컴퓨터 제어와 전문 작업 수행 능력 강화. 정렬(Alignment) 개선과 더 안전한 자율 수행이 핵심

흐름 한 줄: 사전학습 → 스케일 확장 → 대화형 정렬 → 멀티모달 → 에이전트 → 컴퓨터 사용

참고

  • MoE (Mixture of Experts) = 모델 안에 전문가 여러 명을 두고, 질문마다 필요한 전문가만 불러서 쓰는 구조. 크지만 효율적.
  • 옴니(omni) = "모든 것". 글·이미지·음성을 한 모델이 다 처리
  • AI Co-worker = AI 동료. 도구처럼 쓰는 게 아니라 같이 일하는 동료처럼

10. 추론 모델 vs 비추론 모델 ★#

시험 포인트

비교 문제로 나오기 좋은 최신 내용입니다.

구분 추론 모델 (Reasoning Model) 비추론 모델 (Standard Model)
동작 질문을 받으면 내부적으로 '생각의 사슬(Chain-of-Thought)'을 거치며 스스로 논리적인 단계를 나누어 검토한 뒤 최종 답변을 냄 질문을 받으면 그동안 학습한 패턴을 바탕으로 가장 확률이 높은 단어를 실시간으로 빠르게 뱉어냄
비유 깊게 고민하고 문제를 푸는 수학자 상식 퀴즈에 바로바로 답하는 퀴즈 달인
장점 복잡한 문제를 정확하게 빠름
예시 OpenAI: o1, o1-preview, o1-mini, o3
Gemini: 1.5 pro, 2.0 flash thinking
Claude: 3.5 Sonnet		 GPT-4o, Gemini 1.5 Flash, Claude 3.5 Haiku 등

참고

추론 모델은 답하기 전에 속으로 풀이 과정을 쭉 써보는 모델입니다. 6장의 CoT(생각의 사슬) 를 모델이 스스로, 기본으로 하는 셈이에요. 그래서 느리지만 어려운 문제에 강합니다.
